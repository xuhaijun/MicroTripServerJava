# 微旅途后端 · 本地环境运维手册（Windows，无 Docker）

> 覆盖范围：**本机开发 / 测试环境**的搭建、配置、部署运行、日志监控与日常运维。
> 服务器部署（Nginx / systemd / 防火墙）见《部署指南》第 6 章，本文不重复。
> 本手册所有步骤均于 2026-09-10 在 Windows 11 23H2 实机走通验证。

---

## 1. 环境要求与检测

### 1.1 依赖清单

| 组件 | 要求 | 用途 | 缺失时的安装方式 |
|---|---|---|---|
| JDK | 21（必须） | 运行时 | `winget install EclipseAdoptium.Temurin.21.JDK` |
| Maven | 3.9+（必须） | 构建 | `winget install Apache.Maven` |
| Redis | 可选 | 令牌吊销跨实例共享（默认内存实现，不装也能跑） | 已装版：`C:\Program Files\Redis`；服务名 `Redis` |
| MySQL | 可选 | 真实数据库验证（默认 H2 文件库，不装也能跑） | `winget install Oracle.MySQL`（装的是 MySQL Server 8.4） |
| Docker | **不需要** | — | 本手册全程无 Docker |

关键认知：**H2 文件库是默认数据源**，MySQL / Redis 都是可选的能力 profile。
最小闭环（JDK + Maven）就能注册、同步、统计、登出全链路。

### 1.2 一键自检

```bash
bash scripts/check-env.sh
```

输出逐项 ✓/✗，有阻塞项会标红并给出安装命令。也可以手工核对：

```bash
java -version          # 应显示 21.x
mvn -version           # 应显示 3.9.x 且 Java 21
redis-cli ping         # 可选：PONG 表示 Redis 在跑
mysql --version        # 可选：8.4.x
netstat -ano | grep -E ":(3306|6379|3000)"   # 看端口占用
```

> Git Bash 里跑 `mvn` 有坑：会执行 sh 版并把 `MAVEN_HOME` 当 Unix 路径传给 Java，
> 报「找不到主类 Launcher」。**在 Git Bash 里请用 `mvn.cmd`**，PowerShell / cmd 直接 `mvn` 即可。

## 2. MySQL 本地安装与初始化（无 Docker）

### 2.1 安装

```powershell
winget install --id Oracle.MySQL --silent --accept-package-agreements --accept-source-agreements
# 安装目录：C:\Program Files\MySQL\MySQL Server 8.4\
```

### 2.2 初始化数据目录（root 空密码，仅本机）

```bash
mkdir -p /d/mysql-local/data
"/c/Program Files/MySQL/MySQL Server 8.4/bin/mysqld.exe" \
  --initialize-insecure --datadir=D:/mysql-local/data --console
```

### 2.3 启动服务

前台调试用 `--console`；长期用注册成 Windows 服务：

```bash
# 方式一：前台（关窗口即停）
"/c/Program Files/MySQL/MySQL Server 8.4/bin/mysqld.exe" \
  --datadir=D:/mysql-local/data --port=3306 --console --character-set-server=utf8mb4

# 方式二：注册为 Windows 服务（开机自启，推荐）
"/c/Program Files/MySQL/MySQL Server 8.4/bin/mysqld.exe" --install MySQLLocal --defaults-file=...
net start MySQLLocal
```

### 2.4 建库建用户

```bash
"/c/Program Files/MySQL/MySQL Server 8.4/bin/mysql.exe" -uroot --skip-password <<'SQL'
CREATE DATABASE IF NOT EXISTS microtrip CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'microtrip'@'localhost' IDENTIFIED BY 'microtrip123';
GRANT ALL PRIVILEGES ON microtrip.* TO 'microtrip'@'localhost';
FLUSH PRIVILEGES;
SQL
```

> 建表不用手工执行：应用启动时 JPA `ddl-auto` 自动建表（users / trajectories / trajectory_points）。

### 2.5 验证字符集（避坑）

查中文时若显示乱码，先加 `--default-character-set=utf8mb4` 再判断——
那多半只是 **mysql.exe 客户端的显示编码问题**，不是存储问题。决定性验证用 HEX：

```bash
"/c/Program Files/MySQL/MySQL Server 8.4/bin/mysql.exe" -umicrotrip -pmicrotrip123 \
  --default-character-set=utf8mb4 microtrip \
  -e "SELECT city, HEX(city) FROM trajectories LIMIT 1;"
# 「成都」的 HEX 应为 E68890E983BD（标准 UTF-8 字节）
```

## 3. 配置：Profile 矩阵

配置采用 **环境 profile × 能力 profile 正交组合**，互不覆盖：

| Profile | 类型 | 作用 |
|---|---|---|
| `dev` | 环境 | 独立 H2 文件库 `data/microtrip-dev`；**限流关闭**；应用日志 DEBUG |
| `test` | 环境 | 独立 H2 文件库 `data/microtrip-test`；限流开启容量放宽到 300；日志 INFO；不强制 HTTPS |
| `prod` | 环境 | 强制外部化 JWT_SECRET / 数据库密码；强制 HTTPS |
| `mysql` | 能力 | 数据源切到 MySQL（读 DB_HOST/DB_PORT/DB_NAME/DB_USERNAME/DB_PASSWORD） |
| `redis` | 能力 | 令牌吊销写 Redis（读 REDIS_HOST/REDIS_PORT），不再走内存实现 |
| `https` | 能力 | 内嵌 Tomcat 启用 TLS（配证书后用） |
| `json` | 能力 | 控制台日志切 Logstash JSON（ELK/Loki 采集用） |

常用组合：

```bash
--spring.profiles.active=dev              # 日常开发：H2，零外部依赖
--spring.profiles.active=dev,redis        # 本机有 Redis，验证跨实例吊销
--spring.profiles.active=test,mysql       # 联调：MySQL 真库
--spring.profiles.active=test,mysql,redis # 联调全量
--spring.profiles.active=prod,mysql,redis # 生产（服务器上用）
```

环境 profile 决定「行为约束」，能力 profile 决定「连什么中间件」，可自由拼装。

## 4. 部署运行

### 4.1 三种启动方式

```bash
# ① 开发态（mvn spring-boot:run，改代码重启快）——日常首选
./scripts/dev.sh          # h2 / mysql / full 三种模式

# ② 生产态验证（真实 jar，与线上一致的产物）
./scripts/run-local.sh

# ③ 直接 java -jar（CI / 脚本化）
mvn package -DskipTests
java -jar target/micro-trip-server-boot.jar \
  --spring.profiles.active=dev --server.port=3000
```

test+mysql 组合的完整示例（本机默认账号）：

```bash
java -jar target/micro-trip-server-boot.jar \
  --spring.profiles.active=test,mysql --server.port=3000 \
  --spring.datasource.username=microtrip \
  --spring.datasource.password=microtrip123
```

### 4.2 启动成功的标志

```
The following 2 profiles are active: "test", "mysql"
Started MicroTripServerApplication in 9.4 seconds
```

```bash
curl -s --noproxy '*' http://127.0.0.1:3000/api/v1/health
# {"time":...,"service":"micro-trip-server","ok":true}
```

### 4.3 全链路冒烟（30 秒验收）

```bash
B=http://127.0.0.1:3000/api/v1
P="139$(date +%s | tail -c 9)"   # 随机手机号

# 注册拿 token
TOKEN=$(curl -s -X POST $B/auth/register -H "Content-Type: application/json" \
  -d "{\"phone\":\"$P\",\"password\":\"Test123456\",\"nickname\":\"冒烟\"}" \
  | python -c "import sys,json;print(json.load(sys.stdin)['token'])")

# 同步一条轨迹 → 查统计 → 登出 → 旧 token 应 401
curl -s -X POST $B/trajectory/sync -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"trajectory":{"id":"smoke_1","start":1757000000000,"distance":5300,"duration":1800,"ascent":120,"descent":98,"avgSpeed":10.6,"city":"成都","pts":[{"lat":30.65,"lng":104.07,"ts":1757000000000}]}}'
curl -s $B/trajectory/stats -H "Authorization: Bearer $TOKEN"
curl -s -X POST $B/auth/logout -H "Authorization: Bearer $TOKEN"
curl -s -o /dev/null -w "%{http_code}\n" $B/trajectory/stats -H "Authorization: Bearer $TOKEN"   # 期望 401
```

## 5. 日志监控

### 5.1 日志文件与滚动策略

`logback-spring.xml` 配置：

| 项 | 值 |
|---|---|
| 文件 | `${LOG_FILE:-application.log}`（相对工作目录，默认在启动目录下） |
| 滚动 | 按天 + 按大小（`SizeAndTimeBasedRollingPolicy`） |
| 单文件上限 | 10MB，超出切分为 `application.log.2026-09-10.0.gz` |
| 保留 | 7 天自动清理 |
| 编码 | UTF-8（文件恒为文本，不受 json profile 影响） |

指定日志位置的两种方式：

```bash
java -jar app.jar -DLOG_FILE=/d/logs/microtrip.log ...     # 不生效（-D 传给 JVM 不传给 logback）
LOG_FILE=/d/logs/microtrip.log java -jar app.jar ...       # ✓ 环境变量方式
```

### 5.2 实时监控常用命令

```bash
# 跟踪滚动前的当前日志
tail -f application.log

# 只看错误
grep -E "ERROR|WARN" application.log | tail -20

# 看 Spring 的启动与 profile 装载
grep -E "profiles are active|Started MicroTrip|Tomcat started" application.log

# dev 环境把应用日志开到 DEBUG（application-dev.yml 默认已开），排查过滤器链/限流判定
```

### 5.3 健康检查与监控端点

```bash
curl -s http://127.0.0.1:3000/api/v1/health         # 业务健康（无需鉴权）
curl -s http://127.0.0.1:3000/actuator/health       # Actuator（有 IP 白名单，见 IpAllowListTest）
```

生产建议：用 `health.sh` 脚本 + 任务计划程序（Windows）/ cron（Linux）做探活，
连续失败时告警。json profile + 文件重定向可直接对接 ELK / Loki。

### 5.4 MySQL / Redis 侧巡检

```bash
# MySQL：连接数与表行数
"/c/Program Files/MySQL/MySQL Server 8.4/bin/mysql.exe" -umicrotrip -pmicrotrip123 microtrip \
  -e "SHOW PROCESSLIST; SELECT COUNT(*) FROM users; SELECT COUNT(*) FROM trajectories;"

# Redis：键数量（吊销令牌会以 revoke: 前缀出现）
"C:\Program Files\Redis\redis-cli.exe" dbsize
"C:\Program Files\Redis\redis-cli.exe" --scan --pattern "revoke:*" | head
```

## 6. 日常运维

### 6.1 备份与恢复

```bash
./scripts/backup.sh                      # H2 / MySQL 数据备份（见脚本内说明）

# MySQL 手工备份
mysqldump -umicrotrip -pmicrotrip123 microtrip > microtrip_$(date +%F).sql
# 恢复
mysql -umicrotrip -pmicrotrip123 microtrip < microtrip_2026-09-10.sql
```

### 6.2 优雅停机

test/prod profile 已开 `server.shutdown: graceful`（30s 排空）：

```bash
# Windows：找 PID 后 taskkill（发 WM_CLOSE 触发优雅停机）
netstat -ano | grep ":3000" | grep LISTENING
taskkill /PID <pid>          # 不加 /F 即优雅；/F 是强杀，仅停机卡死时用
```

### 6.3 数据目录约定

| 路径 | 内容 | 可否删除 |
|---|---|---|
| `./data/microtrip.mv.db` | 默认 H2 库 | 可（丢开发数据） |
| `./data/microtrip-dev.mv.db` | dev 库 | 可 |
| `./data/microtrip-test.mv.db` | test 库 | 可 |
| `D:/mysql-local/data` | MySQL 数据目录 | **不可**（删了=全库没了） |

### 6.4 故障排查速查表

| 症状 | 根因 | 处理 |
|---|---|---|
| 启动报 `Unsupported character encoding 'utf8mb4'` | MySQL URL 的 `characterEncoding` 写了 `utf8mb4`——那是 MySQL 字符集名，不是 Java 编码名 | 必须写 `UTF-8`（Connector/J 8 自动映射 utf8mb4）。已修复，若再现请检查是否有旧 jar |
| 启动报 `LettuceConnection` / pool 相关 ClassNotFound | redis profile 开了连接池但缺 `commons-pool2` | pom 已补依赖；确认 `mvn package` 后 jar 内含该库 |
| 改了配置但行为没变 | **改动没进 jar**（打包在改配置之前） | 重打包后用 `unzip -p target/*.jar BOOT-INF/classes/application-mysql.yml` 验证 jar 内内容 |
| 令牌登出后仍可用 | 没激活 redis profile 时吊销在**内存**里，重启即失效（单机开发可接受） | 需要持久吊销：`dev,redis` / `test,mysql,redis`；验证见 6.5 |
| 429 被限流 | dev 关了限流；test 容量 300/min；默认配置较严 | 联调时用 dev，或 `RATELIMIT_CAPACITY` 环境变量放宽 |
| `mvn` 在 Git Bash 报「找不到主类 Launcher」 | sh 版 mvn 把 MAVEN_HOME 当 Unix 路径 | 用 `mvn.cmd` |
| 端口 3000 被占 | 上次进程没退干净 | `netstat -ano | grep :3000` 找 PID 后 taskkill |

### 6.5 验证「吊销真的写进了 Redis」

```bash
# 登录拿 token 后：
curl -s -X POST $B/auth/logout -H "Authorization: Bearer $TOKEN"
"C:\Program Files\Redis\redis-cli.exe" --scan --pattern "revoke:*"   # 应出现键
curl -s -o /dev/null -w "%{http_code}\n" $B/trajectory/stats -H "Authorization: Bearer $TOKEN"   # 401
```

### 6.6 自动化测试作为部署前关卡

```bash
mvn test     # 68 用例：契约 19 + 性能回归 13 + IP 白名单 17 + Actuator 12 + 限流 1 + stats 契约 6
```

其中 `StatsClientContractTest` 专门守护客户端字段契约（缺失字段会让 App 静默显示 0），
**每次改 DTO 字段名后必须全绿再部署**。
